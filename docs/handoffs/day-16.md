## 1. What was researched

- **What a template is here.** A real DOCX file with real,
  original content (Forma's own — no WPS template, no copied
  text), committed in the project like the blank templates (Day
  15). Applying it creates a new document in the user's library
  from that file (the same Storage + documents + versions pattern
  as `createDocument`). The three templates: **Resume** (a
  one-page professional resume — name, contact, summary,
  experience, education, skills table), **Letter** (a formal
  business letter — sender/recipient addresses, subject, body,
  closing), **Report** (a structured business report — executive
  summary, findings, a quarterly-results table, conclusion,
  recommendations). Personal details are bracketed placeholders
  (`[Your Full Name]`, `[Company Name]`) so it is unmistakable
  that the user replaces them. All three are DOCX only in v1.
- **How a template is built.** python-docx (already installed,
  used for the blank DOCX on Day 15) builds a styled document:
  Title / Heading 1 / Heading 2, normal paragraphs, a table. The
  generator script `scripts/generate-templates.py` is the source
  of truth — it builds the three DOCX files AND their preview
  data, so the preview can never drift from the file.
- **How the preview works (verified on this VM).** A real visual
  preview is possible without the document server: LibreOffice
  headless converts DOCX → PDF (`soffice --headless --convert-to
  pdf`), and `pdftoppm` (already used by the OCR worker) renders
  the first page to PNG. Verified 2026-11-18: a test DOCX
  converted to PDF and rendered to a first-page PNG. The javaldx
  warning is harmless (Java is not needed). The generator renders
  each template's first page to a PNG thumbnail
  (`public/templates/<slug>.png`, served as a static asset) and
  extracts the structured text (headings + paragraphs, in order)
  into `src/lib/templates/<slug>.preview.json`. The gallery shows
  the thumbnail + the first 8 preview lines (with an "…and N more
  lines" note).
- **The data model.** Templates are app-level (not per-user, not
  per-workspace) — a fixed gallery of Forma's own templates. No
  database table in v1: the registry is a pure module
  (`src/lib/templates.ts`) listing id, name, description,
  category, file name, thumbnail path, and the preview (imported
  from the JSON). The server module (`src/lib/templates.server.
  ts`) reads the DOCX bytes (the Day 15 split: pure list
  client-safe, bytes server-only).
- **"Save a custom template" is NOT in this feature.** Turning one
  of your documents into a template needs a per-user template
  store (a table + Storage) — a separate feature, recorded as the
  follow-up in §8.

## 2. Completed functionality

- **The templates.** `src/lib/templates/resume.docx` (37,345
  bytes, 21 preview entries), `letter.docx` (37,058 bytes, 17
  entries), `report.docx` (37,320 bytes, 32 entries) + their

- **The registry.** `src/lib/templates.ts` (pure): `TEMPLATES`
  (id, name, description, category, file name, thumbnail path,
  preview), `isTemplateId`, `getTemplate`. `src/lib/templates.
  server.ts` (server-only): `getTemplateBytes(id)` — reads the
  DOCX from disk, clear error if missing.

  (`templateId` = the enum of the three slugs, `title`,
  `folderId`) + `applyTemplate` in
  `src/features/library/actions.ts` — the createDocument pattern
  (validate, role check, read bytes, upload as v1, insert rows,
  clean up on failure). The file name comes from
  `getTemplateFileName` (renamed from `getBlankTemplateFileName`
  on Day 15 — it builds a file name for a document created from
  a template, blank or named) and the MIME type from
  `ALLOWED_UPLOAD_TYPES.docx`.
- **The gallery.** `/templates` (was a placeholder) now lists the
  three templates: thumbnail, category, name, description, the
  preview text, and a "Use this template" form (title + hidden
  template id) per template. The form is `ApplyTemplateForm` in
  `src/components/library/library-forms.tsx`.

## 6. Security/licensing checks

- No new engine, no new licence: the templates are made by
  python-docx (MIT) and are plain Office files with Forma's own
  content. No WPS template, branding or font is used. The
  thumbnails are renders of Forma's own files.
- No secrets in code. The template id is validated by Zod
  against the known slugs; the title is sanitised before it
  becomes a file name; the editor-role and workspace checks are
  unchanged. The template files are read from the project's own
  files; only the registry (names + preview text) reaches the
  browser.

## 6b. Verification notes and fixes made during Day 16

- **The generator failed on a cross-device rename.**
  `os.replace` from /tmp to the project failed with "Invalid
  cross-device link" (/tmp and the project are on different
  filesystems). Fixed with `shutil.copyfile` + remove.
- **The first e2e run failed 4 checks, and all four were the
  harness, not the code.** (1) The gallery check expected
  "Quarterly Results" in the page, but the gallery shows only
  the first 8 preview lines and "Quarterly Results" is entry 9 —
  the check now asserts what is actually rendered ("Executive
  Summary" + the "…more lines" note). (2–4) The DOCX text check
  searched the raw bytes for the template's text, but the DOCX
  content is deflate-compressed inside the ZIP, so the plain text
  is not visible in the raw bytes. Fixed by extracting
  word/document.xml with `unzip -p` and checking the text there.
  All 30 checks pass after the fixes.

## 7. Known defects and limitations

- **DOCX-only in v1.** No spreadsheet or presentation templates
  yet, and no proposal / invoice / meeting minutes / certificate
  templates yet.
- **No "save a custom template" yet** (needs a per-user template
  store — a table + Storage).
- **The thumbnails show only the first page.** A template with
  more than one page only shows its first page in the gallery.
  The preview text shows the first 8 lines with a "…and N more
  lines" note.
- **LibreOffice and pdftoppm are authoring-time tools** (they do
  not survive a VM reset, and the app does not need them at
  runtime). Regenerating the thumbnails needs them reinstalled.
- **The editor browser round-trip is still unproven** (the
  docserver is down). The applied resume opens as a word document
  (the editor page loads, 200); a human typing in it is the
  missing proof, same as for every other editor feature.
