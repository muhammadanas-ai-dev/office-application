## 1. What was researched

- **The bug.** `createDocument`
  (`src/features/library/actions.ts`) inserted a document row with
  only a title — no `file_path`, no `mime_type`, no `size_bytes`,
  and no `document_versions` row. The button said "New blank
  document" but the result could not be opened in the editor (the
  editor needs a file), had no version 1, and had nothing to
  download. A decorative control, not a working feature.
- **What a blank Office file is.** A DOCX/XLSX/PPTX is a ZIP
  (OOXML) with `[Content_Types].xml`, `_rels/.rels`, and the main
  part (`word/document.xml`, `xl/workbook.xml` +
  `xl/worksheets/sheet1.xml`, `ppt/presentation.xml` +
  `ppt/slides/slide1.xml`). A file made by a real Office library
  (python-docx, openpyxl, python-pptx) is a valid Office file that
  ONLYOFFICE opens as word/cell/slide. Verified on this VM:
  python-docx, openpyxl and python-pptx 1.0.2 all import cleanly
  (python-pptx was installed with `pip install
  --break-system-packages` for this task; pip packages do not
  survive a VM reset, but the generated files do — they are
  committed).
- **Approaches considered.** (1) Generate the blank file in code
  at runtime with a ZIP library — rejected: no ZIP library is in
  node_modules, adding one for three tiny files is the wrong
  weight, and hand-rolling a ZIP writer is error-prone. (2)
  **Committed minimal templates + a generator script (chosen).**
  Three small binary files generated once by
  `scripts/generate-blank-templates.py` and committed in
  `src/lib/blank-templates/`; the script is the source of truth,
  the files are reproducible, a few KB each, version-controlled,
  and verified by the unit tests. (3) Ask the ONLYOFFICE editor
  to create a new document — rejected: it needs the document
  server, which is down.
- **The established pattern.** `uploadDocument` and
  `duplicateDocument` (same file): validate the input (Zod),
  check the editor role, upload/copy the file in Storage at
  `buildStoragePath(workspace.id, newId, 1, fileName)`, insert
  the `documents` row + the `document_versions` row (version 1),
  and remove the uploaded file again if either insert fails.
  `createDocument` now does the same, with the template bytes as
  the file instead of an uploaded one.

## 2. Completed functionality

- **The templates.** `src/lib/blank-templates/blank.docx`
  (36,567 bytes, 17 parts), `blank.xlsx` (4,768 bytes, 9 parts),
  `blank.pptx` (28,104 bytes, 38 parts) — a blank document with
  one empty paragraph, a blank workbook with one empty sheet, a
  blank presentation with one blank slide. Generated by
  `scripts/generate-blank-templates.py` (committed).
- **The modules.** `src/lib/blank-templates.ts` (pure,
  client-safe): `BLANK_TEMPLATE_TYPES` (docx/xlsx/pptx with
  label + MIME type from `ALLOWED_UPLOAD_TYPES` — no second MIME
  table), `isBlankTemplateExt`, `getBlankTemplateType`,
  `getBlankTemplateFileName` (sanitises the title the same way
  the upload sanitises a file name). `src/lib/blank-templates.
  server.ts` (server-only): `getBlankTemplateBytes(ext)` — reads
  the file from disk, and throws a clear error naming the
  generator script if a template is missing, instead of creating
  a title-only document.
- **The schema.** `documentTitleSchema` gained
  `type: z.enum(["docx","xlsx","pptx"]).default("docx")` — a
  missing type means a Document; an unknown type is rejected,
  not silently defaulted.
- **The action.** `createDocument` now: parses the schema,
  checks the editor role, reads the template bytes, uploads them
  to Storage at the v1 path, inserts the documents row
  (file_path, mime_type, size_bytes, version 1) + the version-1
  row, and removes the uploaded file if either insert fails.
- **The UI.** `CreateDocumentForm` has a Document / Spreadsheet /
  Presentation selector (radio buttons, from
  `BLANK_TEMPLATE_TYPES` — not hardcoded in the UI) next to the
  title input.

## 6b. Verification notes and fixes made during Day 15

- **The build caught a real layering mistake.** The first version
  of `blank-templates.ts` imported `node:fs` (to read the bytes),
  and the library form (a client component) imported it for the
  type list — Turbopack failed the build ("the chunking context
  does not support external modules (request: node:fs)"). Fixed
  by splitting the module: the pure type list stays in
  `blank-templates.ts` (no Node imports, client-safe) and the
  byte reading moved to `blank-templates.server.ts`
  (`server-only` + `node:fs`).
- **The suite caught a second, related mistake.** The unit test
  imported the server module, and `server-only` throws in
  vitest (it resolves the default export condition, not the
  `react-server` one). Fixed by having the test read the files
  directly (it is Node code) and by stubbing `server-only` in
  the vitest config — but that stub then exposed a third
  failure: `library-list.test.tsx` renders the list, which
  imports the forms, which import the actions, which now import
  the server module. The stub fixed that too. The app build
  remains the real guard for client/server layering (it caught
  the first mistake); the stub only lets the tests load the
  modules.
- **The probe script was deleted.** `scripts/probe-form-action.
  mjs` was a temporary probe to learn how the create form renders
  (the `$ACTION_REF_n` / `$ACTION_n:0` / `$ACTION_KEY` hidden
  fields); its findings are baked into the e2e harness.

## 7. Known defects and limitations

- **The old title-only rows stay as they are.** Documents created
  before this fix (title only, no file) are still visible in the
  library and still cannot be opened. No migration, no backfill
  — the owner did not ask for one, and deleting or rewriting a
  user's documents without being asked would be wrong.
- **The blank files are minimal.** One empty paragraph, one empty
  sheet, one blank slide. No headers, no default styles beyond
  the libraries' defaults. A template with real content is the
  Templates feature, not this one.
- **python-pptx does not survive a VM reset** (pip packages are
  wiped). The generated files are committed, so the feature does
  not need it at runtime; only regenerating the templates does
  (the command is in the generator script's docstring).
- **The editor browser round-trip is still unproven** (the
  docserver is down). The blank DOCX opens as a word document
  (the editor page loads, 200); a human typing in it is the
  missing proof, same as for every other editor feature.
